# Roadmap

本文件保存长期方向与里程碑；可执行任务卡在 `docs/kanban/issues/`，索引在 `docs/kanban/board.md`。
仓库既有的设计文档惯例（`docs/plans/YYYY-MM-DD-<topic>-design.md`、`docs/pitfalls/`）保持不变，看板与之共存。

## Planning Policy

- 不为每个可能的未来需求预先建卡；详细卡只覆盖当前 1–2 批可执行工作。
- 长期主题、显式否决（YAGNI）的想法放这里，临近时再转卡。
- 一张卡 = 一个可独立验收的会话工作量；L 级任务先拆成 S/M 卡再动工。

## Parking Lot

显式否决/搁置过的想法（有设计留痕，勿轻易重提）：

- 设置里的「资源管理页签」与「应用内检查数据更新」——完整资源管理页签与应用内检查数据更新均评估后 YAGNI（docs/plans/2026-10-08-data-management-design.md）。
- R2/manifest 资产托管方案——域名长期续费成本被否，维持 GitHub + 镜像前缀。
- 启动自动检查更新——违反「联网只发生在首次资产下载和手动检查更新」的产品承诺，明确不做。
- 主窗口位置记忆——屏幕外窗口风险，刻意不记（docs/plans/2026-10-09-window-size-persistence-design.md）。
- 新增设置项——原则上禁止（README「明确不做的功能」）。
