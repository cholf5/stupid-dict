# 下载健壮性：Windows 系统代理接入 + 三相位下载链 + 人工兜底补全

日期：2026-10-08

## 背景与决策

作者在 Windows 全新机器上从零安装：软件自动下载词典/发音包从未成功，
手动从 GitHub Release 下载词典后手动导入成功，发音包下载了却没有导入
入口，至今不可用。结论：中国大陆用户从 GitHub Release 拿数据几乎注定
挣扎，而浏览器（走 VPN/系统代理）是唯一被证明可靠的通道。

讨论过的方案与结局：

- **数据打进安装包**：被否。Windows 的系统 TTS 不可用，发音包同样是
  必需品，只打包词典不解决「必须下载」的本质；三平台全打包又冗余。
- **Cloudflare R2 + 自有域名**：技术上最优（出口流量免费、10GB 免费
  存储、直链支持 Range），被否的原因只有一个——**域名要每年续费，
  「人不在了就没人续费」**，作者不接受任何需要本人永久维护的付费承诺。
- **manifest 源清单**：依赖一个国内可达的长期端点（Gitee raw 需实名
  账号），随 R2 一起被否。
- 最终决策：**托管保持 GitHub（直连 + 镜像前缀），健壮性从代理接入与
  降级顺序里挣出来，人工兜底补全**。

## 改了什么

- **Windows 注册表代理检测**（`ProxyDetector.WindowsSystemProxies`）：
  读 `HKCU\...\Internet Settings` 的 `ProxyEnable`/`ProxyServer`，
  解析 "host:port" 与 "http=h:p;https=h:p;socks=h:p" 两种 WinINET 格式
  （https 优先，socks 走 socks5://，`ParseWindowsProxyServer` 纯函数
  可单测）。此前 Windows 只有环境变量和端口探测，系统代理（Clash 等
  「系统代理」开关的主力人群）完全接不到。
- **三相位下载链**（`BuildAttempts`）：
  1. **平台默认代理**（`HttpClient.DefaultProxy`）过全部源——与用户
     浏览器完全同款的路由，Windows 上连 PAC（AutoConfigURL）都由 .NET
     自己解析，覆盖注册表解析不到的场景；无代理的机器上它就是直连，
     行为与旧版一致。
  2. **绕开一切代理直连镜像**：系统代理是「配置了但已死」（VPN 崩溃
     没还原设置）的机器上，镜像直连必须活着——GitHub 直连不在此相
     （国内直连必死，留在相位 1 即可）。
  3. **显式检测的代理**（环境变量/注册表/scutil/端口探测）各试前两个
     源——覆盖平台默认在 unix 上不读 scutil 的缺口。
- **发音包手动导入**（`ImportAudioPack` + 底部条「选择本地文件」）：
  补上作者亲身踩到的缺口。导入前校验 zip 根部含 uk/ 或 us/ 条目，
  错误的 zip 直接拒绝，不往音频目录里撒垃圾。
- **「用浏览器打开下载页」直链**：词典下载面板与发音包底部条各一个
  `HyperlinkButton`，指向 data-1 发布页——自动下载失败时，用户点链接
  → 浏览器（VPN 生效）下载 → 回来选本地文件导入，两步兜底。

## 机器状态 × 相位覆盖

| 状态 | 相位 1（平台默认） | 相位 2（直连镜像） | 相位 3（显式代理） |
|---|---|---|---|
| 无代理（VPN 关） | =直连,镜像可用 ✓ | ✓ | 兜底 |
| 系统代理活着（VPN 开） | ✓ 全部可达 | 不需要 | 兜底 |
| 系统代理已死（VPN 崩溃未还原） | 挂(每次≤15s) | ✓ | 兜底 |
| TUN 全局接管 | =直连 ✓ | ✓ | 兜底 |

## 评估过、不做

- **并行竞速**（所有源同时探测取最快）：收益是首字节延迟，不是健壮
  性；串行相位已有 15s 首字节超时兜底。YAGNI，留作后续可选项。
- **PAC 本地解析**（读 AutoConfigURL 自己跑 FindProxyForURL）：复杂度
  高，相位 1 交由 .NET 平台默认代理解析，行为与浏览器一致。
- **R2 / manifest**：见背景。

## 验证

- `ProxyDetectorTests`：WinINET 格式解析 9 正例 + 9 反例（空串、无端口、
  非法端口、空 host、纯 ftp、值带空格、scheme 前缀）；BuildAttempts
  相位结构（前 4 平台默认覆盖全部源、直连相 = 3 镜像、其余全部显式代理）。
- `DownloadFlowTests`：错误 zip 导入被拒且不污染目录；正确包导入后
  uk/us 就位。
- Windows 注册表路径的端到端行为需在真机验证（CI 无 Windows 桌面代理
  环境）：开 Clash 系统代理 → 软件应直接走代理下载成功。
