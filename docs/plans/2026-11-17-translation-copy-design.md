# 译文一键复制（2026-11-17）

## 背景与目标

翻译卡出来了，用户下一步几乎总是把它拿走——贴进笔记、发给别人、写成文档。
在此之前只有「选中再复制」：译文是 `SelectableTextBlock`，得拖选或双击选词，
整段复制要三四个动作。目标是一步到位：卡片上点一下就拿到整段译文。

不做新设置（本项目的默认纪律：能自动决定就不加开关），也不改变任何现有行为。

## 做了什么

- 译文下方的 chip 行新增「复制」（英文 `Copy`），点击把整段译文写进系统剪贴板。
  位置与「取消 / 重试 / 配置翻译」同一条视觉节奏：chip 在卡片底部、紧跟内容。
- 反馈复用发音失败闪烁的手法：成功后 chip 短暂变「已复制」，约 1.5s 复原；
  剪贴板不可用或写入失败变「复制失败」（同样 1.5s），点击绝不静默失败、
  也绝不因异常杀进程（`async void` 逃出的异常会直接终止应用）。
- 连点安全：复原目标固定取「复制」文案，而不是「点击前的当前内容」——否则
  第二次点击会把上一轮的「已复制」当成原文记下来，chip 永远停在确认态。
- 文案进 `Translations`（zh 源、en 覆盖），沿用既有的单例本地化链路。key 用通用的
  `Copy` / `Copied` / `CopyFailed`——同一套 chip 反馈后来也被词条页的复制复用
  （见 `2026-11-17-entry-copy-design.md`）。

## 评估过但不做

- **自动复制**（翻译成功即写剪贴板）：会悄悄覆盖用户原本的剪贴板内容，
  属于「替用户做决定」里代价最高的那种。手动一次点击足够便宜。
- **快捷键（如 ⌘⇧C）**：与结果区的文本选择 / 复制语义打架，且需要额外的
  焦点与「复制哪个」判定；应用已有 ⌘K / ⌘[ / ⌘] / ⌘, 四组键，再挤一个
  低频动作用处不大——翻译卡本来就只在句子未命中时出现。
- **点击译文整段即复制**：译文的双击取词（查词）已经在用同一块控件，
  再叠一个单击复制会让拖选变得不确定。
- **复制入口也进托盘迷你查词卡**：那张卡只做单词查词，不渲染翻译卡。
- **复制按钮放设置里开关**：为一次点击开设置项不划算（见「明确不做的功能」）。

## 验证

`TranslationFlowTests.TranslationCopyChipCopiesTranslationToClipboard`：句子未命中
→ 自动翻译成功 → 点「复制」→ headless 剪贴板（`IClipboard.TryGetTextAsync`）里
是对应译文 → chip 显示「已复制」。headless 有剪贴板实现（`HeadlessClipboardImplStub`），
所以这条断言走真实剪贴板 API，不是桩。

## 备注

Avalonia 12 的剪贴板是新的 `IAsyncDataTransfer` 模型：`IClipboard` 上没有
`SetTextAsync`，文本读写走 `Avalonia.Input.Platform.ClipboardExtensions`
（`SetTextAsync` / `TryGetTextAsync`）。照 11.x 的写法会编译失败。
