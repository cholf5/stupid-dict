# 设置「数据目录」页签：词典/发音包状态 + 打开数据目录

日期：2026-10-08

## 背景与目标

需求：评估是否在设置里加一个「资源管理」页签——没下载时可以下载、已下载时可以
打开目录、可以检查词典是否有更新。评估结论：**不加页签**。三个能力里：

- 「没下载时下载」已被主窗口全覆盖：首启下载面板接管（自动下载 / 手动下载 /
  选择本地文件 / 浏览器下载页，`MainWindow` 构造与 `DictionaryDownloadPanel`）、
  词典就绪后自动排队发音包、失败/取消态底栏常驻重试与导入入口、点 UK/US 发现
  发音包缺失时重新拉出底栏（`PlayWord`）。设置里再造一份下载 UI 意味着两处入口
  操作同一条下载链（CTS 与进度状态都在 MainWindow），或把安装链抽成共享服务，
  为一条几乎不会从设置发起的路径付架构成本。
- 「检查数据更新」没有可检查的对象：数据资产钉在 `data-1` prerelease（
  `ReleaseAssets.DataTag`），设计即「一次发布基本不动」；`UpdateChecker` 只读
  `releases/latest` 查 App 版本，数据版本发现机制不存在。
- 「打开数据目录」是真实缺口，且是其他所有手动流程的钥匙：已装用户想更新/修复
  数据（删 `dictionary.db` 或 `audio/` 后重启即回到下载/导入流程），第一步「知道
  文件在哪」目前应用内没有任何入口回答。

目标：以最小形态补真实缺口——「关于」页加数据区块（安装状态 + 打开数据目录 +
数据发布页直链），不加页签、不加设置项（本功能不要求用户做任何决定，与
「新增设置项原则上禁止」的原则无冲突）。

## 做了什么

- `SettingsWindow` 构造注入 `AppLocations?`（生产侧由 `MainWindow.OpenSettings`
  传入自身 `_locations`；测试经 `NewLocations` 注入临时副本，绝不碰真实数据）
  与 `Action<string>? openDataDirectory` 缝（默认实现
  `Process.Start(UseShellExecute: true)`：macOS 走 `open`、Linux 走 `xdg-open`、
  Windows ShellExecute 打开资源管理器，与 `OnOpenLink` 打开浏览器同机制；测试
  注入记录器/抛错桩）。
- 新增「数据目录」页签（置于「关于」前，保持关于殿后的惯例）承载数据区块：
  - 词典、发音包两行安装状态。判定 `File.Exists(DictionaryDatabasePath)` 与
    `Directory.Exists(audio/uk)`——与 `MainWindow.AudioPackInstalled` 同语义，
    在窗口打开时对磁盘求值（不共享 MainWindow 的易变字段）；语言切换时随
    `OnTranslationsPropertyChanged` 重算刷新（状态是稳定事实而非瞬态进度）。
  - 一行目录说明：下载安装的资产在用户数据目录，随安装包携带的在应用目录
    （`AppPaths` 的 exe 同目录优先规则决定的两种布局，打开的目录永远能看到
    history.db，说明文案覆盖差异）。
  - 按钮「打开数据目录」（固定打开 `_locations.DataDirectory`）+ 复用
    「用浏览器打开下载页」（`OpenDownloadPage` 既有文案 + `DataReleasePageUrl`
    直链，Tag 在代码后置赋值）。打开失败写进区块内的状态行。
- Translations 新增 7 条 zh/en 字符串；headless 测试钉住状态翻转、打开目录的
  回调参数、失败文案，并扩展 About 页渲染测试。
- README「词典与资源」补一段已装数据的管理路径。

## 评估过什么、为何不做

- **完整「资源管理」页签**：见背景——下载/导入入口重复建设、模态 + SizeToContent
  窗口里跑 600MB 下载进度体验错位、与 README 第一屏 "No dictionary management"
  的定位打架（本区块定位是排障兜底，不是管理界面）。YAGNI。
- **应用内检查数据更新**：要做版本发现得引入本地数据版本标记（解压时落盘）+
  远端 `.sha256` 对比 + 170MB/570MB 重下的确认交互，而数据更新现实频率约等于
  零，建成大概率闲置。等真要发 `data-2` 时再按最小形态升级本区块（显示数据
  版本 / 跳发布页让用户自查）。YAGNI。
- **「打开数据目录」智能定位到词典实际所在目录**：词典与发音包可能分居两处
  （随包携带词典在 exe 目录 + 下载的发音包落在用户数据目录），智能定位顾此
  失彼；固定打开用户数据目录 + 文案说明两种布局，行为可预期、测试可钉。
- **重装/替换已装资产的按钮**：删文件 + 重启即回到现有下载/导入流程，「打开
  数据目录」已解锁该路径；为低频场景在设置里复刻下载链不值。

## 已知取舍

- 状态在窗口打开时对磁盘求值：设置开着时发音包底栏下载恰好完成不会即时翻转，
  下次打开设置时可见（模态下词典面板的下载不可能进行中，因为主窗口被禁用）。
- 「打开目录失败」错误行是瞬态渲染，保持出现时的语言（既有约定）；状态行与
  行标签随语言切换刷新。
- `OnOpenLink`（数据发布页直链复用的处理器）失败时错误写进检查更新的状态行，
  沿用既有实现不改。

## 修订：区块独立成「数据目录」页签（同日）

首版把数据区块放进「关于」页底部，实现后复核发现：原三页签内容都很短，「关于」
多出区块后设置面板（SizeToContent=Height）切到该页时高度突然涨高，观感突兀。
用户拍板把数据区块独立成第四页签「数据目录」，关于页恢复原高度——「页签 =
管理界面观感」的反对理由让位于实际高度问题；本页签仍是排障兜底（状态 + 打开
目录 + 直链），不含下载按钮与更新检查，与被否掉的「资源管理页签」不是一回事。
其余评估结论（下载入口不重复建设、应用内检查数据更新 YAGNI、固定打开用户数据
目录、不做重装按钮）不变。
