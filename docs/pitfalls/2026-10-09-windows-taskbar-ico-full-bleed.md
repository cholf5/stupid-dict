# Windows 渲染 exe/任务栏图标不加蒙版不缩放：Apple 网格边距烤进 .ico 整幅小一圈

- **状态**：已修复（ico 满幅几何，png/icns 不动），回归测试 `WindowsTaskbarIconArtworkIsFullBleed`（SKBitmap 采样 256 帧 alpha）
- **日期**：2026-10-09
- **背景**：用户拿任务栏截图对比：欧路词典（满幅圆角方块）旁边，本应用图标明显小一圈，「感觉没把 Icon 撑满」；同屏 macOS 无此问题。图标三件套由 `make-icon.py` 从同一母版生成，此前共用 Apple 网格几何。

## 症状与根因

Windows 任务栏/开始菜单/exe 图标渲染出的画面内容比满幅邻居线性小约 19%。量测旧 `app-icon.ico` 256 帧：alpha bbox `(22, 22, 234, 234)`——四边各 22px 透明边距，内容只占画布 82.8%；同 tile 下线性尺寸是满幅邻居的 81%（面积 66%）。

根因是**把 macOS 的图标语义烤进了 Windows 的素材**：

- Apple 图标网格要求内容块四周留透明边距（1024 画布 + 830 内容块 + 97px 边距），因为 macOS Dock/bundle 图标系统语义就是带边距、由系统统一观感——用户「Mac 没问题」正说明这份几何在 macOS 是对的；
- Windows 对 exe 资源图标（csproj `ApplicationIcon`）与窗口图标（`Window.Icon` → 任务栏/标题栏）**按 tile 原生尺寸原样渲染，无系统圆角蒙版、无缩放、不补边**。边距烤进素材多少，画面就缩水多少——ico 的消费端没有任何机制帮它补回来。

当初「圆角必须烤在素材里，三端才能一致」的结论本身没错（运行时图标确实不走系统蒙版），但被过度推广成了「三件套共用同一份几何」：烤**圆角**对三端都成立，烤**边距**只对 macOS 成立。

## 修复

`make-icon.py` 一次跑两套几何，`styled_icon(source, content, radius)` 复用同一实现：

- **png/icns 照旧**：Apple 网格，830/1024 + 半径 194（macOS Dock/bundle 语义要留边）；
- **ico 满幅**：内容撑满 1024 画布，圆角同比例放大 `194/830 → 239/1024`（23.4% 不变，不另造几何、不改形状——「撑满」= 同一形状放大，不是重新设计）。

配套两道防线：

- **脚本自检**：满幅画布 alpha bbox 必须 `(0, 0, 1024, 1024)`、角部必须透明，不满足直接抛——几何回归在生成时即拦截；
- **回归测试** `WindowsTaskbarIconArtworkIsFullBleed`：手解 ICO 目录取 256 帧 PNG，`SKBitmap.Decode`（SkiaSharp 经 `Avalonia.Skia` 传递引用，零新增依赖）采样 alpha——`(0,0)=0`（圆角烤在素材）、`(128,128)=255`、`(3,128)=255`、`(252,128)=255`。判别点是 `(3,128)`：旧边距 ico 此处为 0（边距区），满幅必须 255。

验证：重跑 `make-icon.py design/icon-candidates/b-derp-book-v3-master.png` 后 png/icns sha256 与改前逐字节一致，工作树只有 ico 一个资产变化；7 帧（16…256）全部满幅；全量测试绿。

## 排查教训

1. **图标几何是平台语义，不是素材属性**。「三端一致」要拆开问：一致的是**形状处理**（圆角烤进素材，因为三端都不加工），不是**画布占用**（macOS 要边、Windows 要满）。跨平台素材管线里每件产物的消费端渲染规则（有无蒙版/缩放/补边）要单独核实，别让一个正确结论（烤圆角）顺手夹带另一个不成立的（烤边距）。
2. **素材几何问题用一个量测数定位**。alpha `getbbox()` 一个数就坐实根因（`(22,22,234,234)` vs `(0,0,256,256)`），和 ScrollViewer 那次 Extent/Viewport 量测同款打法——别对着截图猜「是不是导出错了」。
3. **回归测试别依赖 Skia 的 ICO codec 选帧行为**：手解 ICONDIR/ICONDIRENTRY（16 字节定长表项，宽高字节 0 表示 256）自取目标帧，再 `SKBitmap.Decode` 解 PNG 载荷。Pillow 帧编码（PNG↔BMP）变了测试也不受影响——解码器两边都认。
4. **预览图必须按消费端真实所见渲染**。脚本的深/浅底 16/24/32/48px 预览此前一直用母版（带边距）当候选列，代表不了 Windows 任务栏观感——这次把候选列换成满幅 ico 才第一次「预览即所见」。做预览工具时先问：这个画面是谁渲染的、按什么规则。
